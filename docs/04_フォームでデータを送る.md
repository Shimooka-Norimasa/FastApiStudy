# 第4章 フォームでデータを送る

## この章のねらい

- ブラウザの入力フォームから、サーバーへデータを送る方法を学ぶ
- `GET` と `POST` の違い、送信後の **リダイレクト** を理解する

## この章が終わるとできること

- HTML フォームの値を FastAPI で受け取れる
- 入力したメモが一覧に追加される「メモアプリ（メモリ保存版）」が作れる
- データを保存しないとサーバー停止で消えてしまうことを体験し、データベースの必要性がわかる

---

## 4-1. 完成するもの

```
メモ
[牛乳を買う       ] [追加]
・パンを買う
・電話をする
```

入力して「追加」を押すと一覧に増えます。ただし保存先は Python のリストなので、**サーバーを止めると消えます**。

## 4-2. HTML フォームの仕組み

```html
<form action="/add" method="post">
    <input type="text" name="content" required>
    <button type="submit">追加</button>
</form>
```

| 属性 | 意味 |
|---|---|
| `action="/add"` | 送信先の URL |
| `method="post"` | 送信方法（POST） |
| `name="content"` | **送るデータの名前**。Python 側の引数名と一致させる |
| `required` | 空のままだと送信できないようにする（ブラウザの機能） |

ボタンを押すと、ブラウザは `POST /add` に `content=入力した文字` を送ります。

### GET と POST の違い

| | GET | POST |
|---|---|---|
| 用途 | データを **見る** | データを **送る・変更する** |
| データの場所 | URL に付く (`?a=1`) | リクエストの本体（URL に出ない） |
| 例 | ページを開く、検索 | 登録、更新、削除 |

**データを変更する操作は POST を使う** のが基本ルールです。

## 4-3. Python 側（`main.py`）

```python
from fastapi import FastAPI, Form, Request
from fastapi.responses import HTMLResponse, RedirectResponse
from fastapi.templating import Jinja2Templates

app = FastAPI()
templates = Jinja2Templates(directory="templates")

memos = []   # データの保存先（ただのリスト）


@app.get("/", response_class=HTMLResponse)
def index(request: Request):
    return templates.TemplateResponse(request, "index.html", {"memos": memos})


@app.post("/add")
def add(content: str = Form()):
    memos.append(content)
    return RedirectResponse(url="/", status_code=303)
```

### ポイント1: `@app.post`

`@app.get` の代わりに `@app.post` と書くと、POST リクエストを受け付けます。

### ポイント2: `content: str = Form()`

- `= Form()` を付けると、「**HTML フォームから送られてきた値**」として受け取ります。
- 引数名 `content` は、HTML の `name="content"` と一致させます。
- `Form()` を付けないと、FastAPI はクエリパラメータ（第2章）だと思ってしまいます。
- フォームの値を読むには `python-multipart` ライブラリが必要です（第0章でインストール済み）。

### ポイント3: リダイレクト（PRG パターン）

```python
return RedirectResponse(url="/", status_code=303)
```

追加処理のあと、HTML を直接返すのではなく、**「`/` を開き直してください」とブラウザに指示（リダイレクト）** しています。

```
ブラウザ                         サーバー
  │ ① POST /add (content=牛乳)   │
  │ ───────────────────────────▶ │ memos に追加
  │ ② 303「/ を開き直して」       │
  │ ◀─────────────────────────── │
  │ ③ GET /                      │
  │ ───────────────────────────▶ │
  │ ④ 一覧の HTML                │
  │ ◀─────────────────────────── │
```

これを **PRG（Post → Redirect → Get）パターン** といいます。
もしリダイレクトせずに HTML を返すと、ブラウザの「再読み込み」でもう一度 POST が送られ、**同じデータが二重登録** されてしまいます。

`status_code=303` は「別の URL を **GET で** 開き直して」という意味のコードです。

## 4-4. テンプレート側（`templates/index.html`）

```html
<ul>
{% for memo in memos %}
    <li>{{ memo }}</li>
{% else %}
    <li>メモはまだありません</li>
{% endfor %}
</ul>
```

Jinja2 の `for` には `else` を付けられます。**リストが空のときだけ** `else` 部分が表示されます。

## 4-5. 動かしてみる

```powershell
cd C:\FastApiStudy\step04_form
uvicorn main:app --reload
```

1. http://127.0.0.1:8000 を開き、メモをいくつか追加する
2. ブラウザで再読み込みしても二重登録されないことを確認
3. **ターミナルで `Ctrl + C` でサーバーを止め、もう一度起動する** → メモが消えている！

データをずっと残すには、ファイルやデータベースに保存する必要があります。次の章で SQLite を学びます。

## 4-6. 練習問題

1. 入力欄をもう1つ増やし（例: `name="author"`）、「メモ（書いた人）」の形で表示してみよう
   - ヒント: `def add(content: str = Form(), author: str = Form()):`
   - リストには `{"content": content, "author": author}` のような辞書を入れるとよい

## まとめ

- フォームは `<form action="送信先" method="post">`、入力欄の `name` が Python の引数名
- フォームの値は `引数: str = Form()` で受け取る
- データを変える処理は POST、処理後は `RedirectResponse(url, status_code=303)` で一覧へ戻す（PRG）
- Python の変数に入れただけのデータは、サーバーを止めると消える
