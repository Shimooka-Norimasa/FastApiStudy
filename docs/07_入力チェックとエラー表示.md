# 第7章 入力チェックとエラー表示

> ここから **応用編** です。基本編（第0〜6章）で作った ToDo アプリを、1章ずつ改良していきます。

## この章のねらい

- 「ユーザーはおかしな入力をするもの」という前提で、アプリを壊れにくくする
- 例外（エラー）の仕組みと、FastAPI の `HTTPException` を理解する

## この章が終わるとできること

- 空白だけのタイトルや長すぎるタイトルを弾き、画面にエラーメッセージを表示できる
- 存在しない ToDo を操作されたときに 404 エラーを返せる
- エラーを JSON ではなく、見やすい HTML のエラー画面で表示できる

## 7-1. 第6章のアプリの問題点

第6章のアプリには、次のような弱点があります。

| 操作 | 何が起きるか |
|---|---|
| スペースだけ入力して追加 | 空っぽの ToDo ができてしまう（`required` は「空欄」しか防げない） |
| 1万文字のタイトルを追加 | そのまま保存されてしまう |
| `/delete/999`（存在しない id）に POST | 何も起きないのに、成功したかのように一覧へ戻る |
| 存在しない URL を開く | `{"detail":"Not Found"}` という JSON が出て、利用者には意味がわからない |

> **ブラウザのチェックだけでは不十分**
> HTML の `required` や `maxlength` はブラウザが行うチェックで、開発者ツールを使えば簡単に外せます。
> **サーバー側で必ずチェックする** のが Web アプリの鉄則です。
> この章では、サーバー側のチェックを確かめやすいよう、入力欄の `required` を外しています。

## 7-2. 例外（エラー）の仕組み

Python では、処理を続けられない問題が起きたことを **例外** で知らせます。

```python
raise ValueError("おかしな値です")   # raise で例外を「投げる」
```

`raise` すると、その場で関数の処理が中断されます。
FastAPI では **`HTTPException`** を `raise` すると、指定したステータスコードのエラーレスポンスが返ります。

```python
from fastapi import HTTPException

raise HTTPException(status_code=404, detail="指定された ToDo が見つかりません")
```

### よく使うステータスコード

| コード | 意味 | この教材での使いどころ |
|---|---|---|
| 200 | OK（成功） | 通常の表示 |
| 201 | Created（作成した） | 第9章 API での追加 |
| 204 | No Content（成功、返す内容なし） | 第9章 API での削除 |
| 303 | See Other（別の URL を開き直して） | 第4章からの PRG |
| 400 | Bad Request（リクエストがおかしい） | 入力エラー |
| 404 | Not Found（見つからない） | 存在しない ToDo、存在しない URL |
| 422 | Unprocessable Entity（型・形式が合わない） | FastAPI の自動チェックのエラー |

## 7-3. 入力チェック（`main.py`）

```python
MAX_TITLE_LENGTH = 100


def validate_title(title: str) -> str | None:
    """タイトルをチェックし、問題があればエラーメッセージを返す（問題なければ None）"""
    if title == "":
        return "やることを入力してください"
    if len(title) > MAX_TITLE_LENGTH:
        return f"{MAX_TITLE_LENGTH}文字以内で入力してください（現在 {len(title)} 文字）"
    return None
```

- `-> str | None` は「文字列 **または** None を返す」という型ヒントです。`|` は「または」の意味です。
- `None` は「何もない」を表す Python の特別な値です。ここでは「エラーなし」の意味で使っています。
- `len(title)` で文字数がわかります。
- `MAX_TITLE_LENGTH` のように **全部大文字の変数** は「途中で変えない値（定数）」という慣習です。

```python
@app.post("/add", response_class=HTMLResponse)
def add(request: Request, title: str = Form()):
    title = title.strip()   # 前後の空白を取り除く

    error = validate_title(title)
    if error:
        todos = database.get_all_todos()
        return templates.TemplateResponse(
            request,
            "index.html",
            {"todos": todos, "error": error, "title": title},
            status_code=400,
        )

    database.add_todo(title)
    return RedirectResponse(url="/", status_code=303)
```

- `title.strip()` … 文字列の前後の空白・改行を取り除きます。`"   "` は `""` になるので、空白だけの入力も「空」として弾けます。
- `if error:` … `error` が `None` 以外（＝エラーメッセージがある）なら、という意味です。Python では `None` や空文字 `""` は「偽」として扱われます。
- エラーのときは **リダイレクトせず** に、エラーメッセージと入力値を付けて一覧画面をそのまま表示し直します。リダイレクトすると、エラーメッセージや入力した文字を次の画面に引き継げないためです。

## 7-4. エラーメッセージの表示（`templates/index.html`）

```html
{% if error %}
    <p class="error">{{ error }}</p>
{% endif %}

<form action="/add" method="post" class="add-form">
    <input type="text" name="title" value="{{ title }}" placeholder="やることを入力">
    <button type="submit">追加</button>
</form>
```

- `error` を渡したときだけ、赤いメッセージが表示されます。
- `value="{{ title }}"` で、入力していた文字を入力欄に戻します（せっかく打った文字が消えるとがっかりするので）。
- 通常の表示では `title` を渡していませんが、Jinja2 は **未定義の変数を空文字として表示** するので問題ありません。

## 7-5. 存在しない ToDo への操作を 404 にする

`database.py` に1件取得の関数を追加しました。

```python
def get_todo(todo_id: int):
    """1件取得。見つからなければ None を返す"""
    conn = get_connection()
    row = conn.execute("SELECT * FROM todos WHERE id = ?", (todo_id,)).fetchone()
    conn.close()
    return row
```

`main.py` では、操作の前に存在をチェックします。

```python
def get_todo_or_404(todo_id: int):
    """ToDo を取得する。見つからなければ 404 エラーにする"""
    todo = database.get_todo(todo_id)
    if todo is None:
        raise HTTPException(status_code=404, detail="指定された ToDo が見つかりません")
    return todo


@app.post("/delete/{todo_id}")
def delete(todo_id: int):
    get_todo_or_404(todo_id)        # 無ければここで中断され、404 が返る
    database.delete_todo(todo_id)
    return RedirectResponse(url="/", status_code=303)
```

- `is None` は「None かどうか」を調べる書き方です（`== None` ではなく `is None` と書くのが Python の慣習）。
- 同じチェックを `toggle` と `delete` の両方で使うので、関数にまとめています。

## 7-6. HTML のエラー画面を出す（例外ハンドラー）

`HTTPException` をそのまま使うと、`{"detail": "..."}` という JSON が返ります。
画面を見ている人向けには、HTML のエラー画面を出したいところです。
そこで **例外ハンドラー**（例外が起きたときに呼ばれる関数）を登録します。

```python
from starlette.exceptions import HTTPException as StarletteHTTPException


@app.exception_handler(StarletteHTTPException)
def http_exception_handler(request: Request, exc: StarletteHTTPException):
    return templates.TemplateResponse(
        request,
        "error.html",
        {"status_code": exc.status_code, "detail": exc.detail},
        status_code=exc.status_code,
    )
```

- `@app.exception_handler(例外の種類)` … その種類の例外が起きたら、この関数でレスポンスを作る
- `exc` には投げられた例外が入っており、`exc.status_code`（404 など）と `exc.detail`（メッセージ）を取り出せます
- `import ... as 別名` … 読み込んだものに別の名前を付けます。FastAPI の `HTTPException` と名前がかぶるので、区別するために別名にしています

> **なぜ `starlette` の HTTPException を指定するの？**
> FastAPI は **Starlette**（スターレット）という別のライブラリを土台にして作られています。
> 「存在しない URL」の 404 は Starlette 側の `HTTPException` で発生します。
> FastAPI の `HTTPException` は Starlette のものを元にしているので、Starlette 側を指定すれば **両方まとめて** 受け取れます。

`templates/error.html`:

```html
{% extends "base.html" %}

{% block title %}エラー {{ status_code }}{% endblock %}

{% block content %}
    <h1>エラー {{ status_code }}</h1>
    <p class="error">{{ detail }}</p>
    <p><a href="/">一覧に戻る</a></p>
{% endblock %}
```

## まとめ

- サーバー側で必ず入力をチェックする（ブラウザのチェックは外せる）
- 入力エラーはリダイレクトせず、メッセージと入力値を付けて画面を表示し直す
- `raise HTTPException(status_code=404, detail="...")` で処理を中断してエラーを返す
- `@app.exception_handler` でエラーの見た目を変えられる
